# Unchecked memory accesses in library/Plank/Plank (inventory for the checked-access build)

Library: Plank master 3a6a28a (Plank-Lab pin). Generated by `fuzz/tools/checked-inventory.py` from the
checked-access rewriter's `sites.tsv` (Plank.Fuzzing.Checked/README.md) plus this hand-written review. Regenerate:
build with `-p:PlankCheckedAccess=true`, then
`python3 fuzz/tools/checked-inventory.py library/Plank/Plank/obj/Release/net10.0/checked-access/sites.tsv fuzz/notes/unchecked-access-sites.header.md fuzz/notes/unchecked-access-sites.md`.

Scope: every `Unsafe.*`, `MemoryMarshal.*`, `Vector*.LoadUnsafe/StoreUnsafe`, X86 pointer loads/stores and gathers,
pointer dereference/indexing, `fixed`, `new Span<T>(void*, int)`, `ref span[i]`, `Buffer.MemoryCopy` in the 224
library files and in Plank.InternalGen's generated `DeltaBinaryPackedDecoder.FastInteger.g.cs` (bit-unpacking
miniblocks, 400 KB). Span indexing, slicing, `BinaryPrimitives` on spans, `MemoryMarshal.Cast/AsBytes/Read` are
bounds-checked by the runtime and only listed as "safe".

"Bound applied" is what the checked build enforces at run time. The *logical* span is the span the ref was taken
from (`GetReference(payload)` -> the page payload slice the caller passed, not the buffer behind it), so a read past
`payload.Length` throws even if the bytes behind it belong to the same pooled allocation.

## Outside this build

- `third_party/K4os.Compression.LZ4` (vendored LZ4 codec, its own assembly, pointer code throughout): not rewritten.
  Guard pages cover its allocations; its block/frame bounds are the codec's own.
- Code generated by Plank.SourceGen into *consumer* assemblies (row types in Plank.Fuzzing): `Unsafe.Add(ref
  GetArrayDataReference(slot._columnN), index)` over row-API slot arrays. Not rewritten (it is not library source);
  agent guard's `-p:PlankGuardArrays=true` page-guards those arrays (catches #276). The library side of the row API
  (`RowReaderCore.GetCurrent`) is checked (above).
- Provenance limits (README): accesses whose base cannot be attributed are counted as "unknown"
  (`PLANK_CHECKED_STATS=1`); on the committed seeds about 1-2 % of checks.
