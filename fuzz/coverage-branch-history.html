How to read the history

These are discrete coverage snapshots, not a time-weighted curve; points are ordered by run completion time. Coverage reports are not available for every historical run, and only four-ISA sets whose run logs contain both the replay completion marker and Coverlet summary are shown. “Ever observed” unions branch hits across consecutive snapshots with an identical instrumented branch set and resets when that set changes.

Coverage percentages are comparable only when the code revision, compiler-generated branch shape, target filters, and corpus are comparable. Reader and writer campaigns use different corpora and can have different durations; their curves describe the coverage observed in each target-specific run. The source and instrumentation denominator can change between snapshots, so a falling percentage can reflect newly introduced branches or changed instrumentation rather than lost fuzzing progress. Corpus contents and fuzzing duration may also differ; reports alone do not establish equal fuzzing effort.
