# Mission: smallest compressed timestamp column from C

Produce the smallest final Parquet file for the supplied ordered values. Your workspace is an
independent C laboratory: it contains no Plank or .NET source, and your candidate must compile and
run as a C program. The trusted gate builds the fixed Parquet metadata around your physical pages.

## Correctness and runtime

- Read exactly 225,000,000 little-endian `int64` values from `/input/values.i64le`, in order.
- Emit a `PQCOL01` bundle as documented in `COLUMN_FORMAT.md`.
- Bundle payloads must use the advertised standard Parquet value encoding and compression codec.
- The gate supplies required `TradeTimestamp: timestamp[us, tz=UTC]`, exact page/row-group
  statistics, ColumnIndex, OffsetIndex, and the fixed file envelope.
- Unchanged PyArrow and DuckDB must decode exactly the reference values.
- The isolated, one-core reproduce run must finish within the cap in `current.json`.

The score is the byte length of the complete gate-assembled `.parquet` file. Lower is better.
Intermediate encoded size is diagnostic only: an encoding that grows before compression may still
win after compression.

## Research surface

Focus deeply on the column itself: delta block shape and bit packing, reset points, data-dependent
page boundaries (especially around disruptive negative deltas or series transitions), transforms
that remain a standard encoding, compression level and advanced codec parameters, and interactions
between all of those choices. The starter's equal-sized pages and exposed arguments are examples,
not limits; edit or replace `candidate.c` when deeper changes are useful.

Do not spend time on schema names, footer fields, created-by strings, metadata ordering, page-header
serialization, or indexes. They are generated by trusted code and are identical consequences of
your page records.

## Timeboxed behavior

- You have 15 minutes. Inspect the starter and current shared results, claim one materially distinct
  subject with the lock board, run cheap discriminating samples, then reserve time for a full bundle.
- Read `/coordination/RESULTS.md` before claiming and before pivoting. Do not duplicate an active
  subject. A losing exact configuration does not refute nearby ideas.
- Concurrent wall time is noisy. Submit a smaller complete bundle even if its local run seems slow;
  the isolated gate is authoritative.
- Keep all implementation in C. System C headers and compression libraries are available. `make`
  and direct `cc`/`gcc`/`clang` commands are supported.

For a candidate, write `submission/candidate.column` and root `submission.json` using
`research/submission.schema.json`. `prepare_argv` compiles the program; `reproduce_argv` only runs it
against `/input/values.i64le`. If no full candidate is ready, submit a scoped observation instead.
Never claim a direction is refuted or exhausted.
